### Баги

- [x] **Нижнє меню «стрибає» при переході на «Улюблені».** Компактне меню і `--nav-safe` (коміт `de5ddbf`) не допомогли. У Chrome-емуляції висота однакова (50px) — потрібно відтворити на реальному пристрої (уточнити: модель, браузер чи встановлений PWA). Гіпотези:
  1. `BottomNav` гідрується (`client:load` у `Layout.astro`) — перерендер після завантаження. Навігація не має стану, тому її можна зробити звичайним `.astro`-компонентом без гідрації (мова — через `data-*` або обидва підписи з `hidden`).
  2. «Улюблені» — коротка сторінка без прокрутки: браузер показує/ховає свою панель і змінює `env(safe-area-inset-bottom)` / висоту в’юпорта. Перевірити `min-height: 100dvh` у `body` vs `100svh`, спробувати фіксовану висоту без `env()`.
  - Зроблено (28.10): меню — статичний `BottomNav.astro` без гідрації (підписи через `html[lang]`); відступ під home indicator лише в `display-mode: standalone`, у вкладці браузера `--nav-safe: 0`. **Перевірити на телефоні.**
- [x] **Сторінка деталей прокручується горизонтально** (від опису до списку акторів; трейлер теж ширший за екран). Ймовірна причина: `.page` у `global.css` — `display: grid` без `grid-template-columns: minmax(0, 1fr)`, тому рядок акторів (`.h-scroll`, `nowrap`) розтягує колонку на всю свою ширину, а з нею — трейлер і опис. Виправлення: `grid-template-columns: minmax(0, 1fr)` для `.page` (або `min-width: 0` дітям). Додати e2e з трейлером і 12 акторами + `expectNoHorizontalScroll`.
  - Зроблено (28.10): `.page { grid-template-columns: minmax(0, 1fr) }`; e2e «details page with a trailer and many actors fits the screen width» (до виправлення сторінка була ширшою на 1074px).

  - UI: горизонтальні ряди постерів (як фільмографія актора) після акторів; ♡ на постері — опційно.
  - Тести: unit на вибір ключових слів і фільтри; e2e з мокнутими рядами.
- [ ] **Плашка перекладу яскравіша** — зараз перекреслене «UA» сіре; зробити контрастнішим (наприклад, `--danger` фон з білим текстом або жовтий акцент).
- [ ] **Бажана мова перекладу — вибір користувача.** Замість жорсткої перевірки лише українського: у фільтрах/налаштуваннях обрати бажану мову (UA, EN, PL…, можна кілька). Плашка показується, якщо перекладу бажаною мовою немає; назва й опис беруться цією мовою (TMDB `language`), з фолбеком. Подумати, чи фільтрувати результати лише з перекладом (опція «Лише з перекладом»). Зберігати як налаштування на пристрої (як «Не показувати» жанри).

## 1. Поточний стан

- Astro (`output: 'server'`, `@astrojs/node` standalone) + Svelte 5, дані з TMDB через власні `/api/*` (ключ лише на сервері).
- Сторінки: `/` (каталог), `/details/[mediaType]/[id]`, `/person/[id]`, `/favorites`, `/offline` (пререндерена).
- Улюблені — `localStorage['movie-finder-favorites-v1']`, лише на цьому пристрої.
- Мова (uk/en) і тема (dark/light) — `localStorage['pet-locale-mode']`, `['pet-theme-mode']`.
- Перевірки: `npm run ci` (format, typecheck, 26 unit, 10 e2e з мокнутим API, build). CI — GitHub Actions на кожен push; `pre-push` хук запускає `npm run ci` локально.

### Як працює PWA

| Що                        | Стратегія                                     |
| ------------------------- | --------------------------------------------- |
| JS/CSS/іконки, `/offline` | precache                                      |
| Сторінки (SSR)            | NetworkFirst (5 с), фолбек — `/offline`       |
| `/api/*`                  | NetworkFirst (8 с), до 200 відповідей на добу |
| Постери `image.tmdb.org`  | CacheFirst, до 400 шт. на 30 днів             |

Конфіг — `pwa.config.mjs`, реєстрація SW — `src/layouts/Layout.astro`.

## 3. Чекліст до робочого використання

### 3.1 Обов’язково перед релізом

- [x] Створити репозиторій на GitHub, `git remote add origin …`, закомітити й запушити. — `END-i/pet-movies`.
- [x] Додати CI (GitHub Actions: `npm ci`, `npx playwright install --with-deps chromium`, `npm run ci`) і `pre-push` хук, як у cards. — `.github/workflows/ci.yml`, `.githooks/pre-push` (вмикається через `npm install` → `prepare`).
- [ ] **Деплой (безкоштовно, для кількох користувачів).** Без HTTPS PWA не встановиться. Зараз деплою немає зовсім: лише CI-перевірки. Варіанти (ліміти безкоштовних планів перевірити на момент деплою):

  | Варіант                  | Що змінити в коді                        | Плюси                                                             | Мінуси                                                                                       |
  | ------------------------ | ---------------------------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
  | **Vercel** (Hobby)       | адаптер `@astrojs/vercel` замість `node` | деплой з GitHub на кожен push, превʼю для гілок, не «засинає»     | Hobby — лише некомерційне використання; serverless: кеш і rate limit в пам’яті на інстанс    |
  | **Cloudflare** (Workers) | адаптер `@astrojs/cloudflare`            | щедрий безкоштовний ліміт запитів, швидко з України, не «засинає» | runtime не Node: перевірити `astro:env` і `fetch`; кеш в пам’яті короткоживучий              |
  | **Render** (Free)        | нічого, `node dist/server/entry.mjs`     | адаптер `node` як є, кеш у пам’яті працює повноцінно              | «засинає» після ~15 хв простою, перше відкриття — до хвилини; для PWA це погано відчувається |

  Рекомендація: **Vercel** — найменше роботи і стабільно для кількох людей. Код готовий: на Vercel адаптер `@astrojs/vercel` вмикається сам (`VERCEL=1`), кроки — у README, розділ «Деплой на Vercel». Лишилось: підключити репо у Vercel, задати `TMDB_API_KEY`, перевірити встановлення PWA з телефона. Rate limit тоді додатково можна зробити на рівні платформи (Vercel Firewall).

- [x] **Ключ TMDB на сервері.** Перевірити, чи Astro вбудовує `TMDB_API_KEY` у збірку під час `build`, чи читає зі змінних середовища під час роботи. Надійніше перейти на `astro:env` (`envField.string({ context: 'server', access: 'secret' })`), щоб ключ задавався на хостингу й не потрапляв в артефакт збірки. — зроблено: `astro:env` (secret), у `dist/` ключа немає, читається з оточення під час роботи.
- [x] **Атрибуція TMDB** — вимога умов використання API: логотип TMDB і текст «This product uses the TMDB API but is not endorsed or certified by TMDB» (наприклад, сторінка «Про застосунок» або футер). — текст і посилання — у футері на всіх сторінках (`AppFooter.svelte`). Лишилось: офіційний логотип TMDB з themoviedb.org/about/logos-attribution.

Кеш — `src/lib/cache.ts` (у пам’яті процесу).
- [ ] Ручна перевірка на реальних iPhone і Android: встановлення, запуск з іконки, офлайн (відкрита раніше сторінка, улюблені, `/offline` для нової сторінки), оновлення версії.

### 3.2 Продуктивність і трафік (важливо для мобільного інтернету)

- [x] **N+1 запити**: `/api/discover.json` на кожну сторінку робить 1 + до 20 запитів деталей у TMDB (у режимі «Усе» — удвічі більше). Кешувати деталі на сервері (in-memory LRU/Redis на години) або брати жанри з `genre_ids` без окремого запиту. — дані для картки кешуються на 12 год (до 5000 шт., лише потрібні поля), списки — 15 хв, деталі й актор — 6 год; однакові одночасні запити об’єднуються. Повторне відкриття сторінки каталогу — 1 запит у TMDB замість 21.
- [x] **Розміри постерів**: `makeImageUrl` за замовчуванням `w500`, а в списку постер 96px. Використовувати `w185`/`w342` + `srcset`. — за замовчуванням `w342`, `srcset` + `sizes` у всіх списках (`src/lib/images.ts`); працює й для улюблених, збережених зі старими `w500`-посиланнями.
- [ ] `Cache-Control` для HTML-сторінок і статики на рівні сервера/CDN.

## 4. Покращення функціональності

1. **Де подивитися** — TMDB watch providers для UA (Netflix, MEGOGO, Sweet.tv…). Найкорисніше для вибору ввечері.
2. **Нескінченна прокрутка** на телефоні замість пагінації.
3. **Підказки під час пошуку** з затримкою (`/search/multi`), включно з акторами.
4. **Улюблені**: позначка «переглянуто», власна оцінка/нотатка, сортування, перейменування й переміщення між категоріями. Зараз порожня категорія видаляється, щойно з неї прибрано останній фільм; «Загальне» показується завжди.

6. Для серіалів — сезони й епізоди, статус (виходить / завершено).
7. Віковий рейтинг показується за шкалою 0+/6+/12+/16+/18+ (`src/lib/ageRating.ts`): у фільтрі та на сторінці деталей. Фільтр перетворює вік на US-сертифікацію для TMDB (12+ → PG-13, 16+ → R) і працює лише для фільмів — для серіалів TMDB `discover` фільтра за сертифікацією не має; можна фільтрувати на сервері за `content_ratings`.
8. README каже «до вибору категорії запитів немає», а зараз каталог одразу вантажить «Усе» (популярне за 120 днів). Вирішити, що правильно, й оновити опис.

## 7. Ухвалені рішення

| Рішення                                                         | Чому                                                                           |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| SSR + власні `/api/*`                                           | Ключ TMDB не потрапляє в браузер                                               |
| У SW немає `navigateFallback`, лише NetworkFirst + `/offline`   | SSR-сторінок немає в precache; універсальний фолбек ховав би справжні сторінки |
| Двомовний інтерфейс (uk/en), за замовчуванням uk                | Так було задумано в проєкті; переклади — через `tr()` у `src/lib/i18n.ts`      |
| Каталог за замовчуванням — «популярне за 120 днів»              | «Найновіші» показували нові релізи без рейтингу й перекладу                    |
| RU завжди виключається з результатів (за ISO-кодом країни)      | Вимога проєкту; тепер без хибних збігів                                        |
| Трейлер — заставка, iframe лише після тапу (`youtube-nocookie`) | Економія трафіку на телефоні, менше трекінгу                                   |
